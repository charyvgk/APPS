Central flagging — sequence with pros

One API of record; SDKs evaluate with a project namespace; every change is audited.

sequenceDiagram autonumber actor Client participant SDK as App + SDK participant API as Central Flag API participant NS as Namespace Store actor Ops as Admin / Ops participant Audit as Audit Log Client->>SDK: API request SDK->>API: eval(ns=payments, key=checkout_v2) API->>NS: Read namespaced rules NS-->>API: Definition + targeting API-->>SDK: Decision + reason codes API->>Audit: Evaluation sample Ops->>API: Toggle / progressive rollout (RBAC) API->>Audit: Change event SDK-->>Client: Consistent response Note over Client,Audit: Pros: one truth, fast kills, governance, consistent SDK
Interactive pros checklist (expand/collapse)
  • Consistency — identical evaluation semantics across namespaces
  • Speed — kill switches without waiting on app deploys
  • Safety — RBAC, approvals, environment promotion
  • Clarity — namespace ownership is explicit
  • Observability — central change + evaluation audit
  • Reuse — targeting, segments, schedules built once

Every drawback → central capability
